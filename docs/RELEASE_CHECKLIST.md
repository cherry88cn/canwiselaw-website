# CanWise Website Release Checklist

本清单用于网站内容、功能或构建逻辑发布。单纯规则文档更新可以缩小视觉检查范围，但仍需核对差异和远端提交结果。

## 1. 开始前

- [ ] 核验 GitHub 当前账号为 `cherry88cn`
- [ ] 确认仓库和正式分支正确
- [ ] 拉取最新 `main`
- [ ] 检查未提交及未跟踪文件，避免覆盖现有工作
- [ ] 读取适用的工作手册、决定记录及任务相关文档
- [ ] 确认目标正式网址和真正的源文件
- [ ] 确认本次是否已经获得修改及发布授权

## 2. 修改后

- [ ] `git diff` 只包含预期修改
- [ ] 没有密码、密钥、客户资料或其他保密信息
- [ ] 运行 `node scripts/build-site.mjs`
- [ ] 运行 `node scripts/build-site.test.mjs`
- [ ] 运行 `node scripts/check-site.mjs`
- [ ] 核对中英文内容、金额、法律术语及内部链接
- [ ] 涉及页面时检查桌面端和手机端布局
- [ ] 检查页面高度、横向溢出、导航、图片和页脚
- [ ] 涉及预约、表单或 intake 时分别检查相应外部功能
- [ ] 涉及新增、删除或合并页面时完成 SEO 和跳转检查

## 3. 提交及发布后

- [ ] 提交信息准确说明本次变化
- [ ] 推送至 `main`
- [ ] 确认远端最新提交编号
- [ ] 检查相关 GitHub Actions 及 Pages 部署状态
- [ ] 等待部署完成后打开正式网址核对实际结果
- [ ] 确认旧网址跳转及关键外部入口仍正常
- [ ] 汇报提交编号、部署结果、正式网址状态及剩余改动
- [ ] 如属重大变更，更新 `docs/CHANGELOG.md`
- [ ] 如形成长期决定，更新 `docs/DECISIONS.md`

## 4. 禁止通过发布流程处理的事项

- 不通过修改 DNS 解决普通构建或缓存问题。
- 不修改任何 Zoho Mail 记录。
- 不更换 GitHub 账号、仓库或技术架构。
- 不使用强制推送、破坏性重置或覆盖无关改动。
